# V1.8.4 社区版：翻译断点恢复与安全重试

## 更新内容
- 选择相同视频、相同语音识别服务商和翻译模型/接口，若应用私有目录中存在有效恢复点，将直接恢复已识别英文并跳过已成功保存的翻译/润色及第三轮校验批次。
- 每个批次的 ID 与非空译文全部验证后，才同步保存完整进度；保存采用临时文件和替换，避免多数情况下写入一半的数据被误当成有效恢复点。
- 即使应用关闭、断网或手动取消，已完成的批次进度仍可以继续使用；字幕全部写入成功后自动清除恢复点。
- 新增「清除未完成翻译进度」，用户可主动从头重做；不会删除已经导出的 ASS。
- 对**明确拒绝的翻译 API 429**，最多调用 3 次（首次 + 2 次有界等待后重试），并检查取消状态。
- 对超时、掉线、HTTP 5xx、无效 JSON 等**可能已计费或结果未知**的失败，不自动重发；用户可重新点击“开始生成字幕”，从最后一个成功保存的批次继续。

## 使用方法
1. 初次选择视频并开始，程序识别英语后自动生成私有恢复点。
2. 如果处理失败或意外关闭，重新打开 App、选择相同的视频，保持 ASR 服务商和翻译服务商、模型、接口不变，再点「开始生成字幕」。
3. 状态栏出现“已找到相同视频的恢复进度”说明成功跳过英文识别并恢复。最后未完成的网络请求可能需要重新发送。
4. 如需全部重新处理，点击「清除未完成翻译进度」，确认后再开始。

## 数据安全、费用与局限
- 恢复数据包含原英文、已翻译中文、字幕时间码与匿名来源指纹，存放在 Android 应用私有文件目录；不写入 GitHub、不保存 API Key。卸载或清除应用数据会移除进度。
- 只保存**一个最近处理的任务**。开始另一视频可能覆盖前一个恢复点；修改 ASR/翻译模型/接口不使用旧进度。
- 来源身份使用内容 URI、文件名、报告文件长度及文件前 64 KB 的摘要。若文件来源不提供长度/数据访问，无法安全确认身份，则停用该次自动续传并从头处理；极端情况下内容更改但摘要和长度碰巧一致，仍有误用可能。
- 恢复省去已经完成的识别和翻译请求，但不保证完全没有重复计费。尤其是已向服务商发出请求、响应却在落盘前中断的批次，重新执行仍可能被计费。
- 仅 HTTP 429 做有限重试；不能承诺所有服务商的 429 均无费用。
- 用户需保持选中的原始视频可访问。离线字幕导出不需要把原视频画面上传。
- 第三方语音识别和翻译依然可能产生 API 费用。
- 目前为社区测试版。CI 通过仅说明静态回归检查和编译通过，实际长视频、断网、杀进程、Android 不同设备的效果仍需真机验收。
