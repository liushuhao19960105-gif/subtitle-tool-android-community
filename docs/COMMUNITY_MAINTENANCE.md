# 社区仓库维护与正式发布边界

## 双仓库原则

- 本公开仓库只接收公开源码、文档和无密钥测试。
- 独立的私有维护仓库保留正式 Android 签名证书、发布配置及此前的开发历史。
- 社区仓库的 GitHub Actions 只执行离线测试和临时 Debug 构建，不生成可覆盖正式签名版本的安装包。
- 社区代码必须审核，之后才可由维护者选择性地移植到私有发布仓库；不能直接从未经审查的公开分支读取 Secrets。
- 不要把原私有仓库完整 git clone/Fork 到此处或合并含私人历史的分支。

## 社区日常流程

1. 用户建立 Issue，使用去隐私化的文字和可复现步骤。
2. 贡献者 Fork、创建分支、提交 PR。
3. 检查 Community CI 的离线测试与 Android Debug 构建。
4. 由项目维护者人工审阅、按主分支保护规则合并。
5. 正式更新由维护者在私有环境重新核验测试、版本号和签名一致性后执行。

## 发布与安全

- 不向社区仓库上传 `.jks`、Secrets、密钥密码，或者签名后的正式 APK。
- 禁止在 PR workflow 中使用 `pull_request_target` 运行不可信代码。
- 推荐设置 main 分支规则：PR 审核、CODEOWNERS、必需状态检查 `Community CI / test`、禁止强制推送、禁止删除分支；这些规则必须在 GitHub Settings 中真正启用。
- 如出现用户隐私和凭据安全事故，暂停发布，并按 SECURITY.md 私下处理。
- 在未做实际兼容性验证前，不把社区测试构建标记为“稳定正式版”。
